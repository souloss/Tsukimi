# Testing and CI

状态：待办

## QA-001 CI 浏览器门禁（P0）

- 目标：让 GitHub Actions 执行 Playwright 核心页面和布局回归。
- 范围：安装固定 Chromium，启动站点，运行 `pnpm test:e2e`；为 CI 设置超时和重试策略。
- 验收：干净 runner 可通过；失败返回非零；不会依赖本地常驻服务器或缓存。

## QA-002 测试产物上传（P1）

- 目标：失败时保留截图、trace、Axe JSON、Lighthouse 报告和服务器日志。
- 范围：配置 GitHub Actions artifact，限制保留时间和大小。
- 验收：人为制造一次失败后能下载全部诊断文件；成功运行不上传无用大文件。

## QA-003 浏览器矩阵（P1）

- 目标：覆盖 Chromium、Firefox、WebKit 和移动设备模拟。
- 范围：区分快速 PR 矩阵和 nightly 完整矩阵，保留必要的浏览器豁免。
- 验收：核心用例在矩阵中稳定通过；失败报告包含浏览器、viewport 和系统信息。

## QA-004 单测覆盖率（P1）

- 目标：为配置合并、feature gate、内容解析和外部数据适配器建立覆盖率目标。
- 范围：引入与当前 Node test/tsx 兼容的覆盖率工具，覆盖正常、边界和错误路径。
- 验收：覆盖率报告可生成；关键目录低于阈值时 CI 失败；不追求无意义实现覆盖。

## QA-005 链接和资源检查（P1）

- 目标：检查站内链接、RSS、图片、文档链接和导航目标。
- 范围：静态页面扫描、站内路由校验和可选外链检查；处理动态/第三方白名单。
- 验收：无失效站内链接；外链失败有分级结果；检查可在无网络环境运行核心部分。

## QA-006 HTML 结构检查（P1）

- 目标：捕获重复 ID、heading 层级、缺失 lang、非法嵌套和空链接。
- 范围：扩展现有 a11y markup 检查，对每个生成页面输出文件定位。
- 验收：问题有稳定规则 ID；生成产物和核心开发页面均可检查。

## QA-007 交互测试（P2）

- 目标：覆盖主题切换、导航抽屉、搜索、分页、密码文章、播放器和设置持久化。
- 范围：用 Playwright 编写用户路径测试，模拟刷新、Swup 转场、localStorage 和网络错误。
- 验收：关键路径有正向、取消、错误和刷新用例；无依赖固定延时。

## QA-008 视觉差异阈值（P2）

- 目标：为截图回归设定可解释的像素差异阈值。
- 范围：固定字体、浏览器、viewport、动画和数据；管理基线更新流程。
- 验收：相同环境重复运行稳定；基线更新必须带任务说明。

## QA-009 测试分层（P2）

- 目标：缩短 PR 反馈并保留完整 nightly 检查。
- 范围：拆分 lint/type/unit/static/e2e/lighthouse/nightly jobs，定义触发条件。
- 验收：普通 PR 时间可控；完整检查仍可手动触发；失败 job 定位明确。

## QA-010 依赖安全扫描（P3）

- 目标：加入依赖漏洞、许可证和过期依赖报告。
- 范围：`pnpm audit`、许可证白名单和可接受风险记录；避免阻塞无关开发。
- 验收：报告可追踪；高风险依赖有明确处理或豁免；锁文件校验通过。

## QA-011 配置变体测试（P1）

- 目标：验证关键 feature gate、主题和部署模式组合。
- 范围：默认配置、可选功能启用/禁用、浅色/深色和移动 viewport。
- 验收：最小代表性矩阵覆盖所有配置分支；每个变体产物和核心页面可启动。

## QA-012 CI 环境一致性（P1）

- 目标：固定 Node、pnpm、Playwright 浏览器和时区，减少环境漂移。
- 范围：workflow、packageManager、缓存 key、环境变量和时间相关测试。
- 验收：本地容器/CI 版本有记录；重复运行结果稳定；失败日志包含版本信息。
